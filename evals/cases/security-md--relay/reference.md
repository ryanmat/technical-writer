# Northwind Relay security policy

Report a security issue in Northwind Relay through the private reporting form or to security@relay.example.com, which acknowledges it within 3 working days and discloses it under a 90-day timeline.

## Supported versions

| Version | Supported |
|---|---|
| 2.5.x | yes |
| 2.4.x | security fixes until 2027-01-31 |
| 2.3 and earlier | no |

## Reporting a vulnerability

To report a security issue, please visit https://github.com/example/relay/security/advisories/new and open a private vulnerability report, or email security@relay.example.com, with a description of the issue, the steps you took to create the issue, affected versions, and, if known, mitigations for the issue. The project prefers the form. For encrypted email, use the project's PGP key, fingerprint [UNVERIFIED: the fingerprint of the PGP key for encrypted reports]. The security team acknowledges your report within 3 working days and tells you whether the issue is confirmed within 10 working days.

## Disclosure policy

This project follows a 90 day disclosure timeline from the acknowledgement. During it the team confirms the issue, prepares the fix, requests a CVE identifier through GitHub, and writes the advisory. You are credited in the advisory by name and affiliation unless you ask not to be. When a fix needs longer than 90 days, the team tells you the new date before the 90 days end.

## Security updates

Fixes land in 2.5.x first, then in 2.4.x while it is supported. They are announced as GitHub security advisories at https://github.com/example/relay/security/advisories and in the release notes at https://relay.example.com/releases.
